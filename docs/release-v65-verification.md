# v65 日常检查与验证

## 发现的问题

用户已确认国内服务为 v64，国际 v63 在任何 fetch 失败时仍提示升级 v63。代码审查同时发现 JSON 请求没有期限：登录或响应正文挂起时，按钮会持续等待。当前公网访问仍未确认根因，不能通过修改提示宣称连通性已修复。

## 完成的改进

- 新增公共网络模块，登录/鉴权 12 秒、匿名诊断 8 秒、邮件发送 25 秒、账号读写 30 秒、其他 JSON 请求 25 秒的整体期限，覆盖连接与 JSON 正文；保留调用方取消信号并清理定时器。
- 连接模块不自动重试，避免重复提交。流式 AI 生成仍走原 fetch 策略，不使用短登录期限。
- 匿名诊断直达实际国内业务服务，忽略账号令牌和 Cookie；区分已知版本、旧版本、HTTP 错误、离线、不可达、错误服务和无法解析的响应。不从 fetch 失败猜测服务器版本。
- 登录页增加可键盘操作、窄屏可滚动的恢复入口，保留本机数据与账号会话乱序保护。
- 新增只读服务器检查脚本；未修改账号、行程、额度、第三方或 HTTPS 配置。

## 线上状态与限制

只读检查国际 `/api/health` 仍返回 v63-pages-entry；国内公网 HTTPS 从本机连接超时。项目清单记录用户确认的国内 v64，不再误标为 v60。没有自动部署国内或国际站。

没有真实用户登录、付费 AI、邮件发送、支付、GPS、酒店库存或手机真机验收。新界面状态使用合成账号与模拟接口，不能作为真实联网登录成功的证明。主要界面新增中文恢复文案，未新增全部语言的翻译覆盖。
