# TripMate v49 / Android 1.1.1

日期：2026-10-26。

## 发现的问题

重试旧账号的登录验证时，如果随即登录新账号，旧验证响应可能晚于新登录返回。v48 在模拟延迟测试中确实出现“B 账号登录成功后又切回 A 账号”。迟到的 401 还可能清空新账号凭证。慢速安全存储写入也可能让旧账号凭证覆盖新账号。

## 本次修复

- 登录、注册、游客进入、验证、退出都有操作顺序；只有最新操作可提交身份变化。
- 旧请求成功、失败或返回 401 都不能覆盖新登录或让已退出账号重新出现。
- 安全存储写入顺序执行；同批某个键失败时，等待其他写入结束后才处理下一账号。
- 退出先清理本机身份，再等待服务器撤销旧凭证；网络慢时也能先完成本机退出。
- 认证组件卸载后，旧响应不再写入本机凭证。

## 安装

手机打开同目录 `TripMate-v49-android-v1.1.1.apk`，直接覆盖上一版。不要先卸载。

电脑 ADB 安装：

```sh
adb install -r TripMate-v49-android-v1.1.1.apk
```

无需操作服务器。账号、行程、额度、离线副本及邮箱、DeepSeek、高德、美团配置保持原状。本轮未访问或部署远程服务器，也未调用真实收费 AI 接口。

## 验证记录

- 修改前用控制响应先后顺序的测试复现：预期 B，实际 A，测试失败。
- 修改后 15 组行为回归通过，覆盖旧成功/401 晚到、退出后响应、慢写入、单键写入失败和组件卸载。
- 原有日期、收藏、额度确认、同步冲突、导航进度和监听清理回归继续通过。
- TypeScript、Android Release 构建、APK 签名和对齐、安装 ZIP 内容在交付时核验。
- 界面交互测试使用 React Native 桩，没有连接真机进行 UI、GPS 或高德唤起测试。

使用系统安全存储保存登录凭证；操作序号仅保存在内存，不改变服务端账号格式。
